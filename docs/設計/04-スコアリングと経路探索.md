# スコアリングと経路探索

## スコア軸

各エッジに以下の 3 軸スコアを計算し、重み付き和を総合スコアとする。

| 軸 | 算出方法 | データソース |
|----|----------|-------------|
| 幅員 | 道路の広さ（狭さは幅員スコアで表現） | `highway`, `width`, `sidewalk` タグ |
| 視界 | 曲率 | `group_nodes` 座標列、（進入エッジ, 退出エッジ）ペア |
| 混在 | 歩行者・自転車との分離度 | `highway` 種別、`sidewalk` タグ |

## 総合スコア

```
総合スコア = α₁ × 幅員 + α₂ × 視界 + α₃ × 混在
```

## エッジコスト

```
cost = 距離 × (1 + λ × (1 - 総合スコア))
```

## CalculateCost

`FoldedEdge` の `segments[]` を反復し、各セグメントの属性で個別にスコアを算出・合算する。`group_nodes` からエッジ内部曲率（視界スコア）を計算する。出力は `ComputedEdge`。

## 交差点曲率計算

交差点に置ける曲率計算は、エッジスコアとは独立に計算する。
曲率計算はエッジスコア

| 項目 | 説明 |
|------|------|
| 時機 | `CalculateCost` 実行中、探索アルゴリズムが交差点を通過する (enter_edge, exit_edge) ペアごとに計算 |
| 入力 | enter_edge の SCC 側終点ベアリング、exit_edge の SCC 側始点ベアリング |
| 計算 | 2 つのベアリングのなす角から回頭の大きさを 0–1 に正規化 |
| コスト反映 | 回頭角度が大きいほど視界スコアが低下（走りづらい） |

コスト式（巡回時）:

```
turn_cost = 距離 × (1 + λ × (1 - turn_score))
          ただし turn_score は回頭曲率から求めた視界スコア（0–1）
```

エッジ内部曲率と SCC 回頭曲率は以下のように分担する:

```
FoldedEdge A ──→ SCC ──→ FoldedEdge B

A の視界スコア = A.group_nodes から計算（エッジ内部曲率）
B の視界スコア = B.group_nodes から計算（エッジ内部曲率）
SCC 通過の視界スコア = (A の終点ベアリング, B の始点ベアリング) から計算

経路全体の視界スコア = A.視界 + SCC.視界 + B.視界
```

## スコアの向き

3 軸のスコアはいずれも 0〜1 で「高いほど安全」。混在スコアは名前に反して「分離度」で、歩行者・自転車と分離されているほど高い（高速道路 1.0、両側歩道 0.8、歩道なし 0.3）。そのため重み付きで足し合わせ、総合スコアが高いほどコストが下がる。

## モードごとのスコア

移動モード（`mode` 指定時）は、幅員スコアと混在スコアの中身をモードごとに変える（`lib/mode_scoring.ts` の `SCORING_PROFILES`、`CalculateCost` の第 2 引数）。モードの定義が無い場合（`mode` なしの API）は従来の計算のまま。

背景:
- 以前の混在スコア（`calculateMixScore`）は、歩行者・自転車にとって最も安全な歩行者専用の道（footway / cycleway / path / steps）を 0.1（最も危険）と評価していた（switch に無い種別の default 分岐に落ちるため）。徒歩・自転車では評価が逆になる
- タグが無い道では幅員スコアも混在スコアも `highway` 種別から推定しており、両者は相関が強かった（どちらも幹線ほど高い）。徒歩で重みを幅員だけ・混在だけにしても、長岡駅→見附駅で同じ経路になった（値そのものは 15 種のうち 12 種で異なる）

### 幅員スコア（幅が分かる道）

国土地理院の幅員区分（約 9 割の区間で分かる）を使う。境目は幅員区分と道路構造令の車線の幅に合わせる。幅が分からない道は従来どおり `highway` 種別から推定する。

| 幅 | 車・バイク | 大型トラック | 意味 |
|----|-----------|-------------|------|
| 3m 未満 | 0.1 | 0.1 | 1 台通るのがやっと |
| 3〜5.5m | 0.4 | 0.2 | 1 車線の道路（標準 4m）。すれ違いが難しい |
| 5.5〜13m | 0.8 | 0.7 | 2 車線（車線の幅 3.0〜3.25m） |
| 13m 以上 | 1.0 | 1.0 | 多車線 |

徒歩・自転車は車道の幅より車との分離が大事なので、幅員スコアは従来どおりとし、重みを小さくする（0.2）。

### 混在スコア（歩道タグが無い道）

`sidewalk` タグは付与率が延長の約 0.5% しかないため、主に `highway` 種別から推定する。`sidewalk` タグがある道は従来どおりそちらを使う。車系は従来どおり（歩行者・自転車から分かれているほど高い）。

| highway | 徒歩（車から） | 自転車（速い車から） |
|---------|---------------|-------------------|
| footway / pedestrian / path | 1.0 | 0.8 |
| steps | 1.0 | （通れない） |
| cycleway | 0.6 | 1.0 |
| residential / living_street | 0.6 | 0.7 |
| unclassified / service / track | 0.5 | 0.6 |
| tertiary | 0.5 | 0.4 |
| secondary / primary / trunk | 0.7（歩道があることが多い） | 0.3（車が速い） |
| その他 | 0.3 | 0.3 |

値はすべて仮の値（統計などの出典は無い）。

## 距離

エッジの距離は `segments[]` の区間長の合計（`utils/haversine.ts` の `distanceOf`）。交差点の仮想エッジ（`MapVCrossEdge`）は 10m とする。

移動モードによっては、`highway` 種別ごとの倍率を区間長に掛けてから合計する（`PathFindOptions.highwayCostFactor`）。幅が分からない track / service を割高にし、抜け道に使わないためのもの。詳細は「06-移動モードと急カーブ」を参照。
