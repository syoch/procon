# 速さと安全の切り替え

> #92。値は仮の値を含む（「仮」と書いたもの）。
> この PR ではサーバー側（所要時間ベースのコスト、`totalTime`、λ の検証）だけを実装する。スライダーと所要時間の表示（画面）は、#92 の後に別 PR で対応する。

## 目的

利用者が「速さ優先」と「安全優先」を切り替えられるようにする。

- 速さ優先: 所要時間が短い経路（多少危ない道も通る）
- 安全優先: 遠回りでも安全な経路（幅が広い・視界が良い・歩行者と分かれた道）

## 現状

エッジのコストは次の式（`path_finder.ts` の `calculateEdgeCost`）。

```
cost = 距離 × (1 + λ × (1 - 総合スコア))
総合スコア = α₁ × 視界 + α₂ × 幅員 + α₃ × 混在   （0〜1、高いほど安全）
```

- λ は「安全をどれだけ重視するか」の強さになっている。λ = 0 なら最短距離、λ を大きくするほど安全な道を優先する
- 全モードとも既定は λ = 1（`MODE_PROFILES[*].defaultParameters`）。このときコストは距離の 1〜2 倍
- `/api/path-find` は `parameters.lambda` を受け取れるので、**サーバー側はすでに λ を変えられる**
- 実測（長岡駅→見附駅、`compare-modes --sweep`）: λ = 0 と λ = 1 の経路の一致率は 0.18〜0.29。λ = 5 では 1〜2 割の遠回りになる

## 方針

### 1. スライダーは λ を動かす（画面は別 PR）

| スライダー | λ | 意味 |
|-----------|---|------|
| 左端（速さ優先） | 0 | 最短（距離または時間） |
| 中央（既定） | 1 | 現在と同じ |
| 右端（安全優先） | 3（仮） | 遠回りしても安全な道 |

- スライダーの値 s（0〜1）から λ を決める。案: s ≤ 0.5 のとき λ = 2s、s > 0.5 のとき λ = 1 + 4(s − 0.5)（中央を今の既定値 1 に合わせる）
- 右端の値（λ = 3）は `compare-modes` で遠回りの度合いを見て決める（仮）
- サーバー側は `parameters.lambda` をそのまま使う。`+server.ts` の zod で 0 以上を検証する（負の値は「危ない道ほど得」になるため）

### 2. 「最短距離」を「最短時間」にする（車系モード）

「速さ」を距離ではなく所要時間で測る。

```
cost = 時間換算の距離 × (1 + λ × (1 - 総合スコア))
時間換算の距離 = 距離 × (基準の速度 60 km/h / 想定速度)
```

- 時間換算の距離は所要時間に比例する（60 km/h の道は距離のまま、30 km/h の道は 2 倍）。単位を距離 [m] のままにすることで、交差点の仮想エッジ（10m）や割高の倍率（`highwayCostFactor`）とそのまま組み合わせられる（`travel_speed.ts` の `travelTimeFactor`）

- 徒歩・自転車は速度がほぼ一定なので、経路は距離のときと変わらない（表示する所要時間だけに使う）
- 車・バイク・大型トラックは、道の種類で速度が大きく違うため、幹線や高速道路を選びやすくなる
- 交差点の仮想エッジ（`MapVCrossEdge`、現在 10m）も、同じ速度で時間に直す（信号の待ち時間は扱わない・対象外）

#### 想定速度

`maxspeed` タグがあればそれを使う（付与率は延長の 5.2%、主に幹線）。無ければ次の表を使う。

| モード | highway | 想定速度 | 根拠 |
|--------|---------|---------|------|
| 徒歩 | すべて | 4.8 km/h（80 m/分） | 不動産の徒歩所要時間の表示ルール（道路距離 80m を 1 分） |
| 自転車 | すべて | 15 km/h（仮） | 出典なし（表示用のみ。経路には影響しない） |
| 車・バイク | motorway | 100 km/h | 高速自動車国道の法定速度 |
| 大型トラック | motorway | 90 km/h | 2024 年 4 月 1 日から 80 → 90 km/h（トレーラーは 80 km/h のまま） |
| 車系 | trunk / primary / secondary / tertiary | 60 km/h | 道路交通法施行令 第11条第1号（中央線などがある一般道路）。幹線は中央線があるとみなす |
| 車系 | unclassified / residential / living_street / service / track（中央線なしと推定） | 30 km/h | 道路交通法施行令 第11条（2026 年 9 月 1 日から）: 中央線・車両通行帯・往復の分離が無い一般道路は 30 km/h |
| 車系 | 同上（中央線ありと推定） | 60 km/h | 道路交通法施行令 第11条第1号 |
| 車系 | *_link（ランプ） | 40 km/h（仮） | 出典なし |

- 道路標識で最高速度が指定されている道は、その速度が優先される（OSM では `maxspeed` タグ）。中央線の無い一方通行の道も 30 km/h（往復の分離が無いため）
- 法定速度は上限であって平均の速さではない（信号・渋滞で実際はもっと遅い）。ここでは「道の種類による速さの違い」を表す目安として使う
- **中央線の有無はタグからほぼ分からない**ので推定する（`hasCenterLine`）。幹線（trunk / primary / secondary / tertiary とそのランプ）は中央線あり。それ以外は `lanes ≥ 2`（付与率 10.4%）か、国土地理院の幅が 5.5m 以上（2 車線ぶん）なら中央線あり。どれにも当てはまらなければ中央線なし（30 km/h）
- `maxspeed` と `lanes` は `map_loader/osm.js` で読み、`OSMEdge` → `Segment` に引き継ぐ（多重辺は大きい方を採る）
- 高速道路では、標識の速度があっても車種の法定速度（大型トラック 90 km/h）は超えない
- 国土地理院の「5.5m 以上」は 2 車線分の幅があるという意味で、中央線が引かれているとは限らない（推定）

### 3. 応答に所要時間を足す

`PathFindResult` に `totalTime`（秒）を足す（mode 指定時のみ。mode なしは null）。画面で「約 ○ 分」と表示できるようにする（表示は別 PR）。信号・交差点の待ち時間や渋滞は含まない。

### 4. 画面（別 PR。UI 担当と相談）

- スライダーの置き場所と見た目、ラベル（「速さ」「安全」）
- スライダーを動かしたときに再検索するタイミング（離したとき／ボタン）
- 所要時間の表示

- あわせて、応答の `widthCoverage`（幅員データの網羅率）の表示も検討する（#90 のレビューで提案）

サーバー側はこの PR で実装し、画面は #92 の後に別 PR で対応する。

## 実装

| 対象 | 内容 |
|------|------|
| `travel_speed.ts`（新規） | 想定速度（`segmentSpeedKmh`）、中央線の推定（`hasCenterLine`）、`maxspeed` / `lanes` の読み取り、時間換算の倍率（`travelTimeFactor`）、所要時間（`travelTimeSeconds`） |
| `mode_profiles.ts` | 各モードに `speed`（徒歩 4.8 km/h・自転車 15 km/h は一定、車・バイクは高速 100 km/h、大型トラックは 90 km/h） |
| `map_loader/osm.js`・`fold2degree.js`・`transient-split.ts`・`app.d.ts` | `maxspeed` / `lanes` を区間まで引き継ぐ |
| `path_finder.ts` | `PathFindOptions.speed` で時間換算の距離にする |
| `pathFind.ts` | `speed` を渡し、応答に `totalTime` |
| `+server.ts` | `lambda` は 0 以上 |
| テスト | 速度・中央線・タグの読み取り、車は速い幹線を選び徒歩は短い道を選ぶこと、`totalTime` |
