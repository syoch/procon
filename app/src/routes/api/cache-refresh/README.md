# POST /api/cache-refresh

OSM キャッシュの失効セルを再取得する

## 定期更新

`POST /api/cache-refresh` が `procon-cache-refresh.timer` から定期実行される。

### 返り値

| フィールド  | 意味                                                         |
| ----------- | ------------------------------------------------------------ |
| `scanned`   | 走査したセル数                                               |
| `expired`   | TTL を超えていたセル数                                       |
| `refreshed` | 更新できたセル数                                             |
| `skipped`   | 取得はできたが空データだったので保存・削除を見送ったセル数   |
| `failed`    | 取得・保存・削除に失敗したセル数                             |
| `regions`   | 1 クエリに含まれた bbox 句の数（HTTP リクエストは常に 1 回） |

`expired === refreshed + skipped + failed` が常に成り立つ。

`failed` または `skipped` が 1 件でもあると HTTP 500 を返す。成功扱いにすると
Overpass の障害が気づけないまま進むため。

### `skipped` の 2 つの意味

`skipped` は「空データで保存しなかった」セル数。处置は `readCache` の結果で分ける。

1. **ディスクのファイルが既に空 / 壊れているセル** → **削除する**
   変更前の実装が残した `{elements:[]}` の残骸がこれ。mtime が更新されないので、
   削除しないと翌晩も同じセルが `skipped` になり HTTP 500 が恒続する
2. **有効データを持つセルに空・部分応答が返った場合** → **削除しない**
   ファイルは失効したままなので翌晩も `skipped` になり 500 が続く。
   一過的な異常応答で**キャッシュ全体を壊さない**ことを優先している

判定に使う `readCache` は空・壊れたデータをヒットにしないので、`null` が
「ファイルが無い / 空 / 壊れている」に対応する。読み取りに失敗した場合
（`EACCES` など）は判断できないため削除しない。

> 「trim が空」≠「ディスクのファイルが空」ではない。`trimOSMData` はセルの外側
> ノードしか含まれない応答でも空を返すので、trim の結果だけを削除条件にすると
> 一過的な部分応答で有効データまで消してしまう。
